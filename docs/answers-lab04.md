# Thảo luận Lab 04

1. Chuẩn bị phiên bản và changelog qua PR vào master để release bắt đầu từ đúng trạng thái đã duyệt.

2. release có thể có phiên bản và changelog dành riêng cho dòng bảo trì. Đưa toàn bộ release ngược vào master có thể làm lùi phiên bản; chỉ chuyển bản vá cần thiết.

3. GitFlow dùng develop và các nhánh release trung gian; quy trình môn học phát triển trên master và giữ nhánh release làm mốc nộp.

4. 1.0.0 đánh dấu bản phát hành ổn định đầu tiên. 0.4.0 vẫn biểu thị giai đoạn phát triển ban đầu.
